```java
// Loads the EMF model
EmfModel model = new EmfModel();
model.setMetamodelFile("metamodel.ecore");
model.setModelFile("model.xmi");
// Set the name by which the model will be
// referred to in the program. Useful if
// the program manages more than one models
model.setName("M");
// Read the contents of the model from disk
// when the model is loaded. Set to false
// to ignore existing model contents (e.g.
// if the model is the target of a 
// model-to-text transformation)
model.setReadOnLoad(true);
// Save any changes made to the model
// when it is disposed
model.setStoredOnDisposal(true);
model.load();

// Parses and executes the EOL program
EolModule module = new EolModule();
module.parse(new File("program.eol"));
// Makes the model accessible from the program
module.getContext().getModelRepository().addModel(model);
module.execute();

// Saves any changes to the model
// and unloads it from memory
// Use model.getContext().
//   getModelRepository().dispose() 
// instead if multiple models are involved
model.dispose();
```

## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

This section outlines the supported conventions in the form of questions and answers followed by relevant examples.

Use a mapping root (setRootAsMap()) and append ScalarNode children to the root's .value using .value.appendNode(...) (mapping-node pattern from the docs). Example EOL program that builds your YAML document from scratch:

```eol
// Create a mapping root
YAMLDoc.setRootAsMap();
var root = YAMLDoc.getRoot();

// Create the scalar nodes for each top-level key
var titleNode         = new ScalarNode("title", "Sensor Reading Snapshot");
var sensorIdNode      = new ScalarNode("sensorId", "SNR-2291");
var temperatureCNode  = new ScalarNode("temperatureC", 21.4);
var activeNode        = new ScalarNode("active", true);
var batteryLevelNode  = new ScalarNode("batteryLevel", 87);

// Representing a null value: create a ScalarNode with null value.
// Note: the docs do not show a null example explicitly, so this
// usage is assumed by analogy to other ScalarNode constructions.
var lastErrorNode     = new ScalarNode("lastError", null);

// Append the nodes to the mapping root (mapping nodes use .value.appendNode)
root.value.appendNode(titleNode);
root.value.appendNode(sensorIdNode);
root.value.appendNode(temperatureCNode);
root.value.appendNode(activeNode);
root.value.appendNode(batteryLevelNode);
root.value.appendNode(lastErrorNode);
```

Notes and caveats:
- The example follows the YAML driver patterns in the docs (mapping nodes use .value.appendNode()).
- The docs show setRootAsList(); by analogy we use setRootAsMap() for a top-level mapping root (this is the standard pattern).
- The handling of a null scalar (lastError: null) is not explicitly shown in the provided docs; creating a ScalarNode with value null is the expected approach, but if your YAML driver/version does not accept null directly you can alternatively omit the key or use an explicit string (e.g., "") depending on the desired output.
- How the YAML is persisted to disk depends on how the YAML EMC model was created/loaded in your environment (saving/disposal is handled by the driver/model setup). The EOL snippet above constructs the in-memory YAML document; saving is performed by the model/driver configuration (not shown in the provided excerpts).
