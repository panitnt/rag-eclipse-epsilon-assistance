## What is the difference between containment and non-containment references in EMF?
Example: demonstrate how containment references enforce unique ownership while non-containment references allow shared relationships in EMF.
Keywords: new Car, new Person

```eol
// Set up a few model elements to play with
var c1 = new Car;
var c2 = new Car;
var p1 = new Person;
var p2 = new Person;
var p3 = new Person;

// p1's car is c1 and p2's car is c2
p1.cars.add(c1);
p2.cars.add(c2);

// p3 is a friend of both p1 and p2
p1.friends.add(p3);
p2.friends.add(p3);

p1.friends.println(); // prints {p3}
p2.friends.println(); // prints {p3}

//add c2 to p1's cars
p1.cars.add(c2);
p1.cars.println(); // prints {c1, c2}
 
// The following statement prints an empty set! 
// As discussed above, model elements can belong to at 
// most 1 containment reference. As such, by adding c2 to
// the cars of p1, EMF removes it from the cars of p2
p2.cars.println();

// Delete p1 from the model
delete p1;

Person.all.println(); // prints {p2, p3}

// The following statement prints an empty set!
// As discussed above, containment references demonstrate
// a cascade-delete behaviour. As such, when we deleted p1,
// all the model elements contained in its cars containment reference
// were also deleted from the model. Note how the friends of p1 (p2 and p3)
// were not deleted from the model, since they were referenced through a 
// non-containment reference (friends)
Car.all.println();
```

── ANSWER ────────────────────────────────────────────────
You should make the YAML root a mapping (because your top-level document has the key "departments"), create a ListNode for "departments" (size 2), and then for each department create the ScalarNode "name" and a ListNode "teams" whose slots are mapping nodes containing a "name" scalar and a "members" list. The example below follows exactly the patterns from the YAML EMC examples (set root, create Mapping/Scalar/List nodes, use .value.at(i).appendNode(...) for list slots and root.value.appendNode(...) for map entries).

Complete EOL script:

YAMLDoc.setRootAsMap();
var root = YAMLDoc.getRoot();

// Create the top-level departments list with 2 departments
var departmentsNode = new ListNode("departments", 2);

// --- Department 1: Prepress ---
var deptName1 = new ScalarNode("name", "Prepress");
var teamsNode1 = new ListNode("teams", 2);

// Team 1: Artwork
var team1Name = new ScalarNode("name", "Artwork");
var members1 = new ListNode("members", 2);
members1.value = Sequence{"Alice", "Bob"};
teamsNode1.value.at(0).appendNode(team1Name);
teamsNode1.value.at(0).appendNode(members1);

// Team 2: Plate Making
var team2Name = new ScalarNode("name", "Plate Making");
var members2 = new ListNode("members", 2);
members2.value = Sequence{"Charlie", "Diana"};
teamsNode1.value.at(1).appendNode(team2Name);
teamsNode1.value.at(1).appendNode(members2);

// Attach name and teams to the first department slot
departmentsNode.value.at(0).appendNode(deptName1);
departmentsNode.value.at(0).appendNode(teamsNode1);

// --- Department 2: Production ---
var deptName2 = new ScalarNode("name", "Production");
var teamsNode2 = new ListNode("teams", 1);

// Team: Printing
var team3Name = new ScalarNode("name", "Printing");
var members3 = new ListNode("members", 2);
members3.value = Sequence{"Ethan", "Fiona"};
teamsNode2.value.at(0).appendNode(team3Name);
teamsNode2.value.at(0).appendNode(members3);

// Attach name and teams to the second department slot
departmentsNode.value.at(1).appendNode(deptName2);
departmentsNode.value.at(1).appendNode(teamsNode2);

// Append the departments list to the root mapping
root.value.appendNode(departmentsNode);

Notes:
- This follows the same node classes and append patterns shown in the YAML EMC examples: new ListNode(name, size), new ScalarNode(key, value), .value.at(i).appendNode(...), and root.value.appendNode(...).
- If you need to persist the YAML to a file, use your environment's way of saving the bound YAML model (the example above builds the in-memory document).
