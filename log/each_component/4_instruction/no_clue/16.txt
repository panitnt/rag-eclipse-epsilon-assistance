## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

You can create that YAML document by building MappingNode and ScalarNode elements and appending them into the document root. The example below follows the API patterns shown in the documentation (new MappingNode, new ScalarNode, .value.appendNode, and YAMLDoc.getRoot()).

Notes about uncertainties from the docs:
- The docs show YAMLDoc.setRootAsList() for making a list root, but they do not explicitly show a setRootAsMapping() method. The example below assumes the document root is a Mapping-style root returned by YAMLDoc.getRoot(). If your environment requires an explicit call to make the root a mapping, call the equivalent API your driver provides (check the YAMLDoc API in your runtime).
- The docs show both root.appendNode(...) and someMapping.value.appendNode(...). If appending to the root fails with one form, try the other (root.appendNode(employeeNode) or root.value.appendNode(employeeNode)).

EOL script (complete, runnable following the documented patterns):

```eol
// Create the nested profile mapping
var profileNode = new MappingNode("profile");
var nameNode = new ScalarNode("name", "Alice");
var departmentNode = new ScalarNode("department", "Prepress");
profileNode.value.appendNode(nameNode);
profileNode.value.appendNode(departmentNode);

// Create the employee mapping and add profile to it
var employeeNode = new MappingNode("employee");
employeeNode.value.appendNode(profileNode);

// Append the employee mapping to the document root
var root = YAMLDoc.getRoot();

// Depending on how the root is represented in your runtime, one of these will apply:
// - If the root is a mapping node: use root.appendNode(employeeNode);
// - If the root exposes a .value with appendNode: use root.value.appendNode(employeeNode);

// Try the mapping-style append first (common in the examples)
root.appendNode(employeeNode);

// If the line above raises an error in your environment, replace it with:
// root.value.appendNode(employeeNode);
```

  profile:
    name: Alice
    department: Prepress
