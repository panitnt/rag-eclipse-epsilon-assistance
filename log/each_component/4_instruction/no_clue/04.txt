## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

Short answer
- Use a MappingNode named "book", append three ScalarNode children for title, author and yearPublished, and attach the MappingNode as the document root.

EOL example (based on the YAML-driver examples in the docs)
Note: the YAML examples in the documentation show creating MappingNode and ScalarNode and using appendNode exactly as below. However the docs only show setRootAsList() explicitly — a method to make the root a mapping (here shown as setRootAsMapping()) and the exact way to append a top-level mapping to the document root are not shown in the provided excerpts. I therefore use the natural equivalents below; if your YAML driver API uses a slightly different root-initialisation or root-append call replace those two lines with the appropriate API call from your runtime.

```eol
// Make the document root a mapping (docs show setRootAsList; setRootAsMapping() is the
// analogous call required to create a top-level mapping root — adapt if your API differs)
YAMLDoc.setRootAsMapping();
var root = YAMLDoc.getRoot();

// Create the "book" mapping node
var bookNode = new MappingNode("book");

// Create and append the scalar children
var titleNode = new ScalarNode("title", "The Quiet Harbour");
var authorNode = new ScalarNode("author", "Elena Marsh");
var yearNode = new ScalarNode("yearPublished", 2019);

bookNode.value.appendNode(titleNode);
bookNode.value.appendNode(authorNode);
bookNode.value.appendNode(yearNode);

// Attach the "book" mapping as the document root entry
// (If your root object exposes .value.appendNode(...) instead of root.appendNode(...),
// use that form. The exact root-append call is not shown in the docs excerpt.)
root.appendNode(bookNode);
```

What to watch for / adjustments
- The documentation examples show setRootAsList() explicitly, but do not show setRootAsMapping() or the exact root-append method. If your YAMLDoc API uses a different name to create a mapping root, call that instead.
- If root has a value container (like root.value.appendNode(...)) use that to append the bookNode instead of root.appendNode(...).
- Once the in-memory document is built you will need to use the YAML EMC driver / resource save mechanism your environment provides to write the YAML to disk (the doc excerpts don’t show the exact save call for YAML).
