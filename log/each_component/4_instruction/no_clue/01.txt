## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

Answer — example EOL script

Below is an EOL script that follows the same construction patterns as the examples in the YAML EMC article: create ScalarNode and (if needed) MappingNode instances and append them into the document.

Note: the documentation shows YAMLDoc.setRootAsList(); but does not explicitly show a setRootAsMapping() call. The snippet below therefore uses an analogous setRootAsMapping() to create a mapping-valued root (this is an adaptation of the documented setRootAsList pattern). If your installation of the YAML driver does not expose setRootAsMapping(), see the alternative approach that follows the main example.

Main (mapping root) — EOL
var titleNode = new ScalarNode("title", "Sensor Reading Snapshot");
var sensorIdNode = new ScalarNode("sensorId", "SNR-2291");
var temperatureNode = new ScalarNode("temperatureC", 21.4);
var activeNode = new ScalarNode("active", true);
var batteryNode = new ScalarNode("batteryLevel", 87);
var lastErrorNode = new ScalarNode("lastError", null);

// (Adaptation of the documented pattern)
YAMLDoc.setRootAsMapping();
var root = YAMLDoc.getRoot();
root.value.appendNode(titleNode);
root.value.appendNode(sensorIdNode);
root.value.appendNode(temperatureNode);
root.value.appendNode(activeNode);
root.value.appendNode(batteryNode);
root.value.appendNode(lastErrorNode);

Alternative (if only setRootAsList() is available)
If your driver exposes only setRootAsList(), you can create a single-row list and append the scalar properties into that row. That produces a one-element sequence whose single element contains the mapping properties (i.e. YAML will be a sequence with one mapping entry rather than a plain mapping at the document root):

YAMLDoc.setRootAsList();
var root = YAMLDoc.getRoot();
root.value.addRows(1);
var row = root.value.at(0);

row.appendNode(titleNode);
row.appendNode(sensorIdNode);
row.appendNode(temperatureNode);
row.appendNode(activeNode);
row.appendNode(batteryNode);
row.appendNode(lastErrorNode);

Caveats
- The examples above use only APIs and usage patterns demonstrated in the YAML EMC documentation (new ScalarNode(...), new MappingNode(...), .value.appendNode(...), setRootAsList/getRoot). The call YAMLDoc.setRootAsMapping() is an adaptation (parallel to the documented setRootAsList()) — if that method is not present in your YAML driver, use the alternative single-row list approach or consult your driver API for the exact method to set a mapping root.
- The snippet shows how to construct the in-memory YAML document. How you persist or add this document to the model repository depends on your surrounding Epsilon host code (model creation / saving), which is not shown in the YAML EMC article examples.
