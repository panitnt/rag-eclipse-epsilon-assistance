## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

Below is a complete EOL script, following the patterns in the documentation examples, that builds the YAML document you provided from scratch.

Primary approach — assume the document root can hold a MappingNode (this follows the same appendNode pattern used in the examples):

```eol
// Get the YAML document root
var root = YAMLDoc.getRoot();

// Create the top-level mapping node "flightLeg"
var flightNode = new MappingNode("flightLeg");

// Create scalar child nodes
var departureNode = new ScalarNode("departureAirport", "BKK");
var arrivalNode = new ScalarNode("arrival_airport", "LHR");
var departureTimeNode = new ScalarNode("departureTime", "2024-07-10T23:45:00+07:00");
var arrivalTimeNode = new ScalarNode("arrival_time", "2024-07-11T06:15:00+01:00");
var mealServiceNode = new ScalarNode("mealService", true);
var extraLegroomNode = new ScalarNode("extra_legroom", false);
var seatNumberNode = new ScalarNode("seat_number", "32A");
var aircraftTypeNode = new ScalarNode("aircraftType", "Boeing 777-300ER");

// Append scalar nodes to the flight mapping
flightNode.value.appendNode(departureNode);
flightNode.value.appendNode(arrivalNode);
flightNode.value.appendNode(departureTimeNode);
flightNode.value.appendNode(arrivalTimeNode);
flightNode.value.appendNode(mealServiceNode);
flightNode.value.appendNode(extraLegroomNode);
flightNode.value.appendNode(seatNumberNode);
flightNode.value.appendNode(aircraftTypeNode);

// Append the flight mapping as the document root's child
// (the examples use appendNode on mapping rows; this follows that same pattern)
root.appendNode(flightNode);
```

Notes / fallback
- The documentation example explicitly shows how to set the root as a list using YAMLDoc.setRootAsList(), but it does not show a distinct API call for setting the root as a mapping. The script above assumes the root can accept appendNode (as mapping rows do in the examples).
- If your environment requires the root to be a list (or appendNode on the root fails), use the documented list-root pattern and add a single row, then append the flight mapping into that row. Example (fallback):

```eol
YAMLDoc.setRootAsList();
var root = YAMLDoc.getRoot();
root.value.addRows(1);
var firstRow = root.value.at(0);

var flightNode = new MappingNode("flightLeg");
// (create and append the same scalar nodes as above to flightNode.value)
firstRow.appendNode(flightNode);
```

If you try the primary script and encounter an error when appending directly to root, use the fallback list-root pattern shown above.
