## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

This section outlines the supported conventions in the form of questions and answers followed by relevant examples.

Note: the EOL examples in the docs create a list-root and add one row, then append MappingNode, ListNode and ScalarNode instances to that row. The script below follows that exact pattern (using MappingNode, ScalarNode, ListNode, Sequence, appendNode, value.at(...) etc.).

createConfig.eol
```eol
/* Create a root with one row and append the top-level entries as nodes on that row */
YAMLDoc.setRootAsList();
var root = YAMLDoc.getRoot();
root.value.addRows(1);
var row = root.value.at(0);

/* server: {host: 0.0.0.0, port: 8443, protocol: https, maxConnections: 500} */
var serverNode = new MappingNode("server");
var serverHost = new ScalarNode("host", "0.0.0.0");
var serverPort = new ScalarNode("port", 8443);
var serverProtocol = new ScalarNode("protocol", "https");
var serverMaxConn = new ScalarNode("maxConnections", 500);
serverNode.value.appendNode(serverHost);
serverNode.value.appendNode(serverPort);
serverNode.value.appendNode(serverProtocol);
serverNode.value.appendNode(serverMaxConn);

/* database: {engine: postgresql, host: db01.internal, port: 5432, poolSize: 20} */
var dbNode = new MappingNode("database");
var dbEngine = new ScalarNode("engine", "postgresql");
var dbHost = new ScalarNode("host", "db01.internal");
var dbPort = new ScalarNode("port", 5432);
var dbPool = new ScalarNode("poolSize", 20);
dbNode.value.appendNode(dbEngine);
dbNode.value.appendNode(dbHost);
dbNode.value.appendNode(dbPort);
dbNode.value.appendNode(dbPool);

/* allowedOrigins: [https://app.example.com, https://admin.example.com, https://staging.example.com] */
var allowedOrigins = new ListNode("allowedOrigins", 3);
allowedOrigins.value = Sequence{
  "https://app.example.com",
  "https://admin.example.com",
  "https://staging.example.com"
};

/* rateLimits: [{tier: free, requestsPerMinute: 60}, {tier: pro, requestsPerMinute: 600}] */
var rateLimits = new ListNode("rateLimits", 2);

/* first rate limit mapping */
rateLimits.value.at(0).appendNode(new ScalarNode("tier", "free"));
rateLimits.value.at(0).appendNode(new ScalarNode("requestsPerMinute", 60));

/* second rate limit mapping */
rateLimits.value.at(1).appendNode(new ScalarNode("tier", "pro"));
rateLimits.value.at(1).appendNode(new ScalarNode("requestsPerMinute", 600));

/* Append top-level nodes to the single root row */
row.appendNode(serverNode);
row.appendNode(dbNode);
row.appendNode(allowedOrigins);
row.appendNode(rateLimits);
```

Notes and caveats
- The EOL code follows the exact construction patterns in the YAML EMC examples: MappingNode, ScalarNode, ListNode, Sequence, appendNode, value.at(...), root.value.addRows(...).
- The docs show setting the YAML model name to "YAMLDoc" in Java; that must match the identifier used in the EOL script (YAMLDoc).
- The docs demonstrate root-as-list usage (setRootAsList()). The examples above therefore create a single row and attach the top-level mapping/list nodes to that row (same pattern used in the documentation). The documentation does not show a setRootAsMapping() call, so if you require the YAML driver to use a mapping root instead of a list containing one row, that API/behaviour is not shown in the provided docs and may need to be checked in the driver implementation.
