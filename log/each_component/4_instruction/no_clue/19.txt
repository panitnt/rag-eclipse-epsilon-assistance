## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

Short answer: build a ListNode for "departments" whose first element is a mapping with a "name" scalar and a "teams" ListNode that contains two mappings with name scalars. The example below shows an EOL script that does this.

Important note about API availability: the documentation examples explicitly show YAMLDoc.setRootAsList() but do not show a YAMLDoc.setRootAsMapping() method. I therefore give two versions:

- Preferred / clearer version (what you would use if your environment provides YAMLDoc.setRootAsMapping()). This produces exactly the YAML you asked for (top-level mapping with key "departments").
- Fallback version using only documented API calls (YAMLDoc.setRootAsList()). This produces the same structure except that the document root becomes a single-element list whose first element is a mapping containing "departments" — functionally similar but not identical to a top-level mapping.

Version A — preferred (may require YAMLDoc.setRootAsMapping(); see note)
```eol
// Set the document root as a mapping (note: setRootAsMapping() is not shown
// in the provided docs; if your YAML driver provides it, use this version)
YAMLDoc.setRootAsMapping();
var root = YAMLDoc.getRoot();

// Create a 'departments' sequence with one department entry
var departmentsNode = new ListNode("departments", 1);

// For the single department entry, set name = "IT"
departmentsNode.value.at(0).appendNode(new ScalarNode("name", "IT"));

// Create the 'teams' sequence with two team entries
var teamsNode = new ListNode("teams", 2);

// Set names for the two teams
teamsNode.value.at(0).appendNode(new ScalarNode("name", "Backend"));
teamsNode.value.at(1).appendNode(new ScalarNode("name", "Frontend"));

// Attach teams to the department mapping
departmentsNode.value.at(0).appendNode(teamsNode);

// Attach 'departments' to the document root mapping
root.value.appendNode(departmentsNode);
```

Version B — documented fallback (uses YAMLDoc.setRootAsList(), guaranteed present in the docs)
```eol
// Use the documented setRootAsList() and create a single top-level row.
// This produces a document whose root is a list with a single mapping that
// has the 'departments' entry. If you need a strict top-level mapping, try
// Version A or check your YAML driver for setRootAsMapping().
YAMLDoc.setRootAsList();
var root = YAMLDoc.getRoot();

// create a single row (mapping) as the document content
root.value.addRows(1);
var docRow = root.value.at(0);

// Create a 'departments' sequence with one department entry
var departmentsNode = new ListNode("departments", 1);

// For the single department entry, set name = "IT"
departmentsNode.value.at(0).appendNode(new ScalarNode("name", "IT"));

// Create the 'teams' sequence with two team entries
var teamsNode = new ListNode("teams", 2);

// Set names for the two teams
teamsNode.value.at(0).appendNode(new ScalarNode("name", "Backend"));
teamsNode.value.at(1).appendNode(new ScalarNode("name", "Frontend"));

// Attach teams to the department mapping
departmentsNode.value.at(0).appendNode(teamsNode);

// Attach 'departments' under the single document row mapping
docRow.appendNode(departmentsNode);
```

If you run Version A and your YAML driver does not provide YAMLDoc.setRootAsMapping(), use Version B. Both examples follow the node creation and append patterns from the YAML EMC documentation (new ListNode, new ScalarNode, .value.at(n).appendNode(...), addRows, etc.).
