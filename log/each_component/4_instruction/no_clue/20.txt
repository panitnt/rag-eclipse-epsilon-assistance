## Querying/modifying YAML documents in EOL
 
The YAML driver uses predefined naming conventions to allow developers to programmatically access and modify YAML documents in a concise way. A type of YAML node must be specified when accessing YAML nodes via the YAML driver. There are 3 types of nodes in YAML:

- `Scalar Node`. Scalar nodes are used to represent a single scalar value (e.g., string, boolean, integer). In the YAML driver, a scalar node consists of a key-value pair, in which the key represents the name of the scalar node, and the value represents the scalar value.
- `Mapping Node`. Mapping nodes are used to represent unordered collections of key-value pairs. In the YAML driver, a mapping node consists of a key-value pair, in which the key represents the name of the mapping node, and the value holds an unordered collection of key-value pairs, which in turn represent other nodes.
- `List (Sequence) Node`. List nodes are used to represent an ordered list of nodes or scalar values. In the YAML driver, a list node consists of a key-value pair, in which the key represents the name of the list node, and the value represents a list of nodes or scalar values.

This section outlines the supported conventions in the form of questions and answers followed by relevant examples.

You can build that YAML document from scratch in EOL using the same node classes and patterns shown in the YAML EMC examples. Below is a complete EOL script that creates the exact structure you posted. It uses the same operations shown in the docs: set the document root as a list, add two list rows, create ListNode and ScalarNode objects, set list-of-scalars via Sequence{...}, and append child nodes into mapping rows.

EOL script (create the YAML structure in-memory as the model named "YAMLDoc"):

```eol
/* Make the top-level document a sequence (the "departments" list) */
YAMLDoc.setRootAsList();
var root = YAMLDoc.getRoot();

/* Add two departments (two rows/items in the root sequence) */
root.value.addRows(2);

/* ---------- Department 1: Prepress ---------- */
/* Create the teams list for Prepress (2 teams) */
var teamsNode1 = new ListNode("teams", 2);

/* Team 1: Artwork */
var team1 = teamsNode1.value.at(0);
team1.appendNode(new ScalarNode("name", "Artwork"));
var members1 = new ListNode("members", 2);
members1.value = Sequence{"Alice", "Bob"};
team1.appendNode(members1);

/* Team 2: Plate Making */
var team2 = teamsNode1.value.at(1);
team2.appendNode(new ScalarNode("name", "Plate Making"));
var members2 = new ListNode("members", 2);
members2.value = Sequence{"Charlie", "Diana"};
team2.appendNode(members2);

/* Fill department 1 row */
var dept1 = root.value.at(0);
dept1.appendNode(new ScalarNode("name", "Prepress"));
dept1.appendNode(teamsNode1);

/* ---------- Department 2: Production ---------- */
/* Create the teams list for Production (1 team) */
var teamsNode2 = new ListNode("teams", 1);

/* Team: Printing */
var team21 = teamsNode2.value.at(0);
team21.appendNode(new ScalarNode("name", "Printing"));
var members21 = new ListNode("members", 2);
members21.value = Sequence{"Ethan", "Fiona"};
team21.appendNode(members21);

/* Fill department 2 row */
var dept2 = root.value.at(1);
dept2.appendNode(new ScalarNode("name", "Production"));
dept2.appendNode(teamsNode2);
```

Notes about running/persistence
- The script assumes a YAML model named "YAMLDoc" is available to the EOL module (the examples use that global). To run this script from Java you would parse this EOL module and add a YamlModel to the module context (see the "How can I delete nodes?" example in the docs for the Java pattern that adds a YamlModel to the module and executes the module).
- The provided documentation examples do not show an explicit API for saving the in-memory YAML model back to disk. The script above creates the YAML structure in the in-memory YAMLDoc model using only APIs shown in the documentation. If you need to persist the model to a file, check your YAML EMC driver's API for a save or write operation (not shown in the provided docs).
