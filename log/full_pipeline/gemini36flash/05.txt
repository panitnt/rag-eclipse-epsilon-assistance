When a template that defines one or more protected regions is processed by the EGL execution engine, the target output destinations are examined and existing contents of any protected regions are preserved. If either the output generated by from the template or the existing contents of the target output destination contains protected regions, a merging process is invoked. The table below shows the default behaviour of EGL's merge engine.

| Protected Regions in Generated | Protected Regions in Existing | Contents taken from |

| On | On | Existing |

| Off | On | Existing |

Question:
What is a protected region in EGL, and what problem does it solve when regenerating code?

Answer:

── ANSWER ────────────────────────────────────────────────
In EGL, a protected region (defined using `startPreserve` and `stopPreserve`) is a block within a template designed for mixing generated code with hand-written code. 

When regenerating code, protected regions solve the problem of accidentally overwriting user edits or hand-written code. When an EGL template is executed, its merge engine inspects the existing target file and preserves the contents of its protected regions, keeping the existing hand-written changes rather than replacing them with the newly generated output.
