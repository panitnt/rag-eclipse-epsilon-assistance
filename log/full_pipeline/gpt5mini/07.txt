# The EGL Co-Ordination Language (EGX)

EGX is a rule-based co-ordination language designed for automating the parametrised execution of model-to-text template transformations. Although built on top of the Epsilon Generation Language (EGL), EGX can in principle work with any template-based model-to-text transformation language. The rationale for this co-ordination language comes from the need to invoke text generation templates multiple times with various parameters, usually derived from input models. To better understand EGX, it is helpful to be familiar with template-based text generation.

    module.getContext().getModelRepository().addModel(model);
    // ... and execute

# The Epsilon Generation Language (EGL)

EGL is a model-to-text transformation (M2T) language that can be used to transform models into various types of textual artefact, including code (e.g. Java), reports (e.g. in HTML/LaTeX), images (e.g. using [Graphviz](https://graphviz.org)), formal specifications, or even entire applications comprising code in multiple languages (e.g. HTML, Javascript and CSS).

EGL is a *template-based* language (i.e. EGL programs resemble the text that they generate), and provides several features that simplify and support the generation of text from models, including: 

- a sophisticated and language-independent merging engine (for preserving hand-written sections of generated text), 
- an extensible template system (for generating text to a variety of sources, such as a file on disk, a database server, or even as a response issued by a web server), 
- formatting algorithms (for producing generated text that is well-formatted and hence readable), and traceability mechanisms (for linking generated text with source models).

── ANSWER ────────────────────────────────────────────────
Short answer: EGL is the template-based model‑to‑text language that describes how to produce textual artifacts from models. EGX is a separate, rule‑based coordination language built on top of EGL whose job is to orchestrate/execution those templates (which template to run, for which model elements, with what parameters, and where to put the generated output).

Differences (from the documentation)
- EGL: a template language for producing text from models (template syntax, merging/protected regions, formatting, traceability). It uses EOL for expressions. (egl.md, articles_egl-patch.md)
- EGX: a rule‑based co‑ordination layer that invokes template transformations in a parameterised, model‑element‑aware way. EGX rules can select elements by type, pass parameters, guard execution, and specify generation targets/locations. EGX is described as “built on top of EGL” and as providing the rationale of invoking templates multiple times with parameters derived from input models. (egx.md, epsilon_and_sirius example, index.md)

Why EGX is needed
- Templates alone describe how to generate text, but real generators must: decide which template to run for which model elements, run them many times with different parameters, and determine target files/locations. EGX provides that coordination and rule semantics so templates can be applied systematically over a model. (egx.md, index.md)
- EGX is deliberately separate so the coordination layer can be reusable and can, in principle, work with any template‑based M2T language. (egx.md)

Honest note: the documentation states EGX “is built on top of EGL” and explains EGX’s coordinating role; it does not explicitly say “EGL cannot perform coordination by itself,” although that limitation is implied by the rationale given for EGX.
